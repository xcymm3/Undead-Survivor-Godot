# 尸潮 CPU 测量与优化方案（2026-10-12）

当前 200～300 只敌人的 CPU 开销已经超过 60 FPS 的 16.67ms 帧预算。敌人已采用二维位置、矩形障碍和允许重叠的软避让，没有逐只 CharacterBody3D。重点应放在共享寻路、密集邻居查询、命中筛选和动画提交。

## 测量条件与边界

- 本机 i5-1235U、12 个逻辑处理器、约 16GB 内存，Godot 4.5.2，真正 headless、Dummy 音频；没有启动桌面游戏或 GPU 渲染。
- 冻结实际工作区源码测量，SHA-256：`139ef5c3cb25c99ae77f879ac0b2af958b9fe1981e69b172aad1aa9c78a96811`。后续报告文字不在该摘要中。
- 50/100/200/300 只普通僵尸；移动、桥口拥堵、持续步枪射击各一轮，预热 60 帧、采样 120 帧。固定模拟 dt=1/60，保持敌人数、玩家无敌与弹药充足，包含真实命中、硬直和实际骨骼提交。
- 另对 300 只做无分段计时探针的两轮对照，第二轮反转场景顺序。移动约 77.8%、拥堵约 80.5%、射击约 70.9% 的敌人仍在移动。
- CPU 段合计 = 模拟 + 动画计算/提交 + 准星检测，并非完整帧或实际 FPS。模拟中的寻路、索敌和射击是子项，不能再加进合计。物理监视器是上下文指标，敌人原生胶囊耗时为 0；原生玩家碰撞与场景射线仍存在。
- 测量不涵盖 GPU、阴影实际绘制、正常死亡/补充人口、精英混合及舞王召唤尖峰。短采样和其他桌面任务会影响最大值，不能据此承诺固定优化比例。

## 建议实施顺序

1. **共享通道寻路并限制密集避让开销。** 当前每只敌人周期性独立跑 A*，邻居查询虽有空间桶，桥口密集时同一桶仍可包含大量敌人。对桥口、栅栏、水晶使用按目标与建筑状态共享的路径或方向场，建筑毁坏时失效；玩家追踪另保留可达路径。把远处索敌分摊到每秒 5～10 次，目标死亡立即失效；局部移动与攻击计时保持原频率。邻居避让只取有限的近邻，拥堵时降低分离强度，继续允许重叠；保留护栏和障碍通行检查。
2. **空间筛选射击和准星候选，复用命中姿态。** `main.gd` 每帧对所有活敌人做准星射线；每发弹丸也遍历全体敌人。利用空间网格沿射线挑选候选，再做部件精确检测，避免扫完整人群。对真正候选按权威时间和敌人状态缓存姿态，准星/弹丸复用；多弹丸、穿透、护甲及爆头规则必须保持。渲染与权威模拟时间不同的姿态不能混用。
3. **骨骼动画按距离和可见性分级。** 当前每个敌人每帧更新 7 个骨骼并强制刷新。先缓存未改变的模型选择，再尝试近处 60Hz、中距离 30Hz、远处 15Hz，屏外停止无用提交；仍根据同一个时间函数插值，命中时按当前权威时间计算真实姿态。优先减少 CPU 提交，批量 GPU 动画可作为后续较大改造。
4. **单独安排隔离 GPU 测量。** 在隔离环境测量可见人群、阴影、夜景灯光和透明效果的 GPU 帧时间，再决定远处阴影关闭、模型 LOD、灯光范围或批量绘制。headless 数据不能证明这些项目的收益。

以上是方案，本次没有实施这些性能改造。先比较每项改造前后同一冻结场景的平均、P95、P99、最大值和超预算帧比例；300 只代表性场景的 CPU 段 P95 ≤10～12ms 是拟议目标，为 GPU 和其余系统留出空间，不能等同于已经达到 60 FPS。还应保留现有桥坡寻路、重叠、水晶攻击、爆头与建筑回归，并补充特殊敌人、持续开枪和舞王召唤的长时间测量。

原始采样位于本机忽略目录 `artifacts/enemy-cpu-profile/results.json`，对照位于 `artifacts/enemy-cpu-control/results.json`；各自包含冻结源码清单。对照旧 `enemy_mix` 标签仍写着爬行混合，但其冻结脚本实际生成全部普通僵尸；本次已修正后续测量工具的标签，未改动对照采样耗时。
