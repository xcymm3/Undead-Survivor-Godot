# Godot 原生组件改造

本轮调整六处实现，保留单人/房主共享权威模拟、MultiMesh 尸群、GPU 与 CPU 命中姿态一致的约束。

## 地图与碰撞

- 游戏直接加载 `scenes/world.tscn`，不再在启动时解析 `world.json` 重建静态地图。
- 静态网格、材质、MultiMesh 实例和碰撞均保存在原生场景中。每个 `Scenery_*` 节点的 `Collision/Shape` 随父节点移动，便于编辑器检查。
- `assets/data/world-collisions.json` 显式列出每个源网格参与碰撞的实例。初次迁移固定了既有碰撞集合；之后不再按实例数量、坐标或合批情况推断碰撞。
- 河床仍由 `river.gd` 生成，与 `Data` 的涉水和敌人高度采样共享定义。静态岸边网格在开发阶段烘焙；调整河岸宽度后需要重新烘焙。
- 开发命令：`powershell -NoProfile -File tools/validate-headless.ps1 -Mode BakeWorld`。此命令完全无窗口，使用 CPU 数据生成原生实例缓冲，不依赖 GPU 回读。
- 更换 `world.json` 后，先检查碰撞清单的几何/材质 ID 和实例列表，再记录新文件的 SHA-256。烘焙器遇到清单与源文件不匹配会拒绝覆盖场景。
- 场景中的 `navigation_obstacles` 元数据保存保守导航边界。改变静态障碍物位置时也需要调整对应边界。运行烘焙会覆盖生成场景，手工场景修改应保留备份或落实到转换输入。

## 绘制与 HUD

正常窗口使用引擎自动渲染循环，菜单动画和异步控件无需手动请求四帧重画。失焦停止绘制；仅软件 Web QA 保留集中限频绘制。

`hud_panel.gd` 使用 Label、ProgressBar、TextureRect 和 Container，统一复用 Theme。文本由原生控件处理省略，状态变化由控件自身刷新。准星、瞄准镜和命中闪烁仍由 Canvas 绘制，仅在相关状态改变时重画。主菜单布局改为依附窗口边缘的锚点。

## 音效

世界枪声、敌人死亡和护甲受击使用有上限的 AudioStreamPlayer3D 池，传入事件实际位置，由引擎处理声像与距离衰减。本地枪声、受伤提示和音乐保持非空间播放。退出/重开停止并清空特效声音。无窗口或 `--silent` 模式只配置资源和路由，不启动音频混音声音；这类检查不能代替实际听感验收。

## 联网显示

客户端保存最多 12 帧权威快照，使用约 100 ms 的显示缓冲，对敌人和远端玩家的位置、角度以及连续动作时间插值。传送、复活、死亡不跨状态插值；丢包时停在最新状态，长时间停顿后重新对齐。离开或重开清空缓冲。

显示数据与 Simulation 分离，客户端仍不提交位置、生命和伤害。本地摄像机沿用最新权威位置的平滑，避免额外显示延迟。广播只压缩编码一次，再复用给各客户端；保留原有协议与可靠性选择，没有改为增量协议。

## 输入与检查

默认按键位于 `project.godot` 的 InputMap，包括移动、开火、开镜、跳跃、换弹、切枪和快捷功能。游戏逻辑通过动作读取输入，不再直接检查固定键码。这里只统一动作层，没有添加改键设置页或完整手柄视角控制。

针对性检查：`powershell -NoProfile -File tools/validate-headless.ps1 -Mode NativeComponents`。覆盖原生地图碰撞、HUD 更新与生命周期、输入改绑、空间音效配置、快照插值与广播编码。该检查已纳入 `npm run verify`。它不能代替 GPU 视觉、听感或发布验收；实际运行结果见 `artifacts/acceptance.md`。
