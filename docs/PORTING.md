# Godot 工程说明

本仓库是从旧项目移植并继续开发的独立 Godot 4.5.2 工程，运行时不依赖 React、Three.js、Electron 或相邻源码目录。Steam 使用与 Godot 4.5 匹配的 GodotSteam 4.16 模板。

## 当前范围

- 工程只保留 `graypine_defense`：保卫水晶，包含吊桥、缓坡、开阔平台与夜间十波连续防守；战前启动第一波，各波投放完成后等待10秒接波，第十波击败舞王后自动清场并通关。当前按十波名单均分预算、向下取整，余数补成名单内1积分僵尸；橄榄球按积分生成。旧基础曲线从138起，增量按 `max(5, round(31 × 0.92^(波次+1)))` 计算，原波次折扣、人数与难度系数计算完毕后，最终预算除以2并向下取整。完整成本和逐波构成见本文末尾的“按类型均分积分生成”。
- 当前提供单人增量玩法与最多4人合作，规则见 [增量玩法与存档](INCREMENTAL.md) 及 [房主存档合作](COOP.md)。ENet局域网与Steam大厅/P2P共用房主权威模拟；客机成长临时跟随房主，收益只保存至房主。
- 跳跃保留世界坐标水平速度，空中输入按方向投影限速逐步加速：加速度 4 米/秒²、输入方向速度上限 1.5 米/秒、总水平速度上限 4.2 米/秒。松键和转动视角保留惯性，反向键逐步减速；空中蹲下不缩放已有速度，墙体碰撞移除受阻速度，落地恢复地面移动。该规则借鉴 Source 空中加速思路，参数适配本游戏，不宣称完全复刻 CS:GO。
- 地形、碰撞、寻路、敌人 CPU 命中姿态和 GPU 显示共享同一组原生规则。
- 玩家固定携带步枪、普通手枪、消防斧和手雷；两把枪使用有限弹药，每次清波各增加 2 个备弹夹，可超过上限。军械库改为开波前商店，金币、钻石、装备、建筑和四种天赋永久保存。其他武器资源仅保留供旧动作与命中专项使用。

## 敌人二维移动

按用户要求撤回 `b0c401a` 与 `dfaf975` 的敌人实体碰撞、按体型导航、物理批量管理和拥堵唤醒实现。敌人主要保存二维 `pos`，用线段与障碍矩形检查移动并沿坐标轴滑动，共用旧版 AStarGrid2D；邻居分离只影响避让方向，允许活僵尸重叠。推搡、受击位移、攻击前移和冲锋也恢复旧版位置计算；僵尸不再作为近战遮挡物。玩家仍使用原生物理与旧版距离阻挡，波次刷新仍保留出生点间距策略。

保留30秒动态分批刷新，波次改为最多十波；保留、炮塔伤害、双武器槽与跳跃惯性。敌人显示与 CPU 命中重新从共享地形计算高度，网络协议为 `undead-survivor-godot-22`。原有 [CPU 测量报告](CPU_PROFILE_2026-09-29.md) 是回退前实现的历史数据，不能代表当前性能；测量工具已适配二维移动，GPU 仍需隔离环境单独测量。

出生使用96×96米对岸林地内20个固定刷新点，每点具有独立、共享的预先验证路线，走到林地外再恢复普通寻路。所有点距吊桥起点至少32米，保持与玩家至少8米距离和敌人出生间距；桥面、本岸及障碍净空内不能生成。77棵树、低矮灌木和22块岩石保留实体与寻路阻挡，树林用MultiMesh批量绘制。出生时检查所有存活玩家眼睛到敌人轮廓的9条射线，涵盖脚、躯干、帽顶和两侧边缘，实际被遮挡才允许生成，不依赖镜头朝向；轮廓由各类模型部件计算并缓存。每次最多检查20个点，不可用时保留配额稍后重试；位置随机数独立于战斗和波次组成。首三波维持10/15/20秒出怪窗口，后续30秒，固定路线不改变积分预算和僵尸种类。

平坦高地纵向长度由82米缩短为54⅔米，坡顶位置不变，后墙前移。水晶位于高地几何中心；商店位于水晶正后方、贴后墙，玩家出生在商店区域正中心。地雷、复活返回点、水晶标牌、照明、道路、岩石和植被随共享布局移动。停止生成爬行僵尸，旧爬行队列条目转换为基础普通；普通类还包含按波次增加占比的路障、铁桶，其他特殊类型保留。爬行资源和人工专项夹具仍保留，用于验证低姿态命中。

永久进度与天赋以 [增量玩法](INCREMENTAL.md) 为准。基础门禁包含 `validate-progression.gd`，自动化不读取或写入玩家进度。本次相关专项覆盖升级后建筑火力、存档与奖励、有限备弹和脱战回血；未运行浏览器、视觉或发布验收。
