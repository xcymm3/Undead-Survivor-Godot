# 静态场景与第一人称渲染优化对照（2026-10-25）

本次实现：关闭所有灯光阴影；商店静态模型按区域、8 米空间块和材质批处理，重复方块使用 MultiMesh，其他单表面模型合并顶点；利用商店门与卧室通道的视锥关系管理室内、卧室、室外静态装饰可见性；第一人称武器仅保留绘制前同步，视口尺寸、世界、MSAA 和分辨率比例仅在变化时设置。

碰撞体和寻路数据保留；旋转展台、老板动作、水晶和建造设施继续由原有逻辑管理。关闭阴影会改变明暗表现。本次没有进行原生 GPU 视觉审查。

## 方法与范围

基线：9ea4837fa5a0c5ebe24fb85e89bf3a2749879d8b。
优化版本：6967b4c8402d7aedc25f61eb69db14695482ecc2。
相同测量脚本注入两份 Git archive 冻结源码。使用同一台 GitHub Actions Windows runner 上的 Chromium / SwiftShader 软件 WebGL，浏览器窗口 960×600（Godot 逻辑视口实际为 1440×900）、同一视角、同一画质配置（渲染比例 0.75、MSAA 关闭、视距档位 1；请求阴影档位 2，优化版本按需求强制关闭），三轮按旧→新、新→旧、旧→新顺序交替，每个场景预热 3 次后采样 8 次，合计每版本每场景 24 次。

测量范围为固定游戏状态下主视图更新、第一人称同步和强制绘制并等待 WebGL finish 的完成时间；不推进物理、寻路或战斗权威逻辑。100 只僵尸场景用于对照模型呈现开销，不代表完整战斗性能。P95 来自 24 个样本，只能作为短时尾延迟参考，不能代替长时间卡顿监测。

本机未启动任何图形进程。云端软件渲染耗时不能换算成本机 Intel Iris Xe 或 Windows EXE 的 FPS，也不能证明偶发两秒卡顿已经解决。

- 商店 459 个可合并静态 Mesh 转为 238 个空间/材质批次：233 个 MultiMesh、5 个合并表面。因按 8 米空间块和区域拆分，不采用整个商店一个超大网格。

- 稳定场景下第一人称 configuration_updates 始终为 2（初始化及画质配置变更）；新增回归检查另外验证连续同步 20 次不重新配置，修改 MSAA 才额外更新一次。相机姿态仍随帧同步。
