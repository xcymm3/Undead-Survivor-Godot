# 尸潮 CPU 独立实验协议

本次只测试 CPU，实验补丁应用于冻结的临时工程，不更改正式玩法。禁止本机图形进程；长采样在 GitHub Actions Windows runner 串行运行。没有真实隔离 GPU，渲染、阴影、灯光、画面验收留待后续。

用户选择先确认 300 只。正式矩阵为移动、桥口拥堵、持续步枪射击，基线、两个独立候选和组合版，每场墙钟预热10秒、采样60秒、5轮；轮次交替顺序。50、100、200和500只采用短采样，不能给出同等置信度。记录平均、P50、P95、P99、最坏尖峰和超过16.67/33.33ms的比例，不把CPU分段合计换算成游戏FPS。

第一阶段独立筛选模型选择缓存、动画分级、16/32候选避让、固定目标共享路径、远处索敌降频、射线空间筛选、权威姿态缓存、对象复用。无骨骼提交、无姿态、5/1骨骼、无避让只用于诊断，不能直接作为上线方案。筛选另含多弹丸、近战、可见和屏外场景；按三个核心场景P95比值几何平均选出两个不同方向的候选，再做正式确认。独立分段探针另运行，不混入收益排名。

固定人口场景使用普通僵尸、高生命建筑和敌人、实际射击与命中路径；每600模拟步恢复起点，使桥口和移动持续存在。这是可重复负载，不是自然波次。动态混合、舞王召唤、死亡生成场景不恢复位置，记录实际模拟时间及存活峰值；更快方案可能推进更多模拟时间，不能忽略人口差异直接排名。十分钟耐久测试固定存活人数、周期性击杀和生成，检查资源周转及尖峰，不称作完整自然对局验收。

测量含权威模拟、CPU动画计算/骨骼提交、准星、第一人称/界面/特效更新。物理监视器单独记录，避免重复加总。Dummy音频仅测路由，不测实际混音。动画分级原型未增加GPU插值，命中仍用权威时刻；上线前需要视觉和手感验证。候选会运行导航、弹道、原生组件检查；涉及射线或动画时加专门对照。

每项保存冻结源码SHA-256、补丁SHA-256、硬件环境和逐帧原始数据。测试途中不修改冻结源；报告拒绝混合源码、无效人口和失败案例。最终结论依赖五轮配对长采样，短筛选仅用于选择候选。
