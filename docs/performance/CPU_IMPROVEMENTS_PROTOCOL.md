# 四项CPU优化与过夜CLI测试

本轮正式实现四项：共享每步的建筑资料并对远处目标进行0.1–0.2秒缓存；准星和枪械弹丸复用保守XZ空间索引；局部避让最多访问32个候选，密集时降低分离强度；敌人移动及玩家可达性路径共用每步12次A*预算，并按近处、被堵和请求年龄安排任务。骨骼、动画与对象池未改。

进入15米范围、目标死亡或建筑导航版本变化会触发重新判断。缓存仅限建筑，不能让玩家离开15米后继续被缓存追踪。索引仅筛选候选，最终仍调用原有精确姿态检测，保留护甲、爆头和穿透；按原名单顺序返回，保持距离相同的命中次序。客户端插值画面使用单独的视觉索引，不能使用权威位置索引。

路径预算可能让新请求短暂排队，优先近处和被堵敌人，年龄增加优先级避免饥饿；仍有路径时沿原路线前进，每步保留障碍、护栏通行检查。目标位置变化或建筑导航版本变化时，失效结果不采用。12次预算包含本步新请求及以前排队的重算。普通模拟中300个同时请求至少需要25步服务，实际负载含多种路径请求，等待时间须结合排队峰值判断。局部避让限额会允许队形更紧，可能提高防线同时承受的攻击量；导航与攻击抽搐回归不能替代真人手感验收。

运行 `node tools/run-cpu-improvements.mjs`。真实headless、Dummy音频，子进程禁止创建窗口；不设置任何定时查询。CLI依次执行基础检查、功能回归、6个版本的短采样、300只长采样、动态场景、十分钟资源周转、生成报告、再次基础检查及报告门禁，最后仅提交推送本次报告。结果目录为 `artifacts/cpu-improvements-night/`，工具演练使用单独目录，不能混入正式数据。

6个版本为：prechange（1940134的原始simulation/main/arena）、cpu_target、cpu_ray、cpu_crowd、cpu_paths，以及cpu_all（本轮四项全部启用）。独立版本只开启对应策略，其他三项关闭；新代码的公共基础设施仍存在，所以独立对照不等于完全逐字还原旧代码。精确旧版对照由prechange提供。每个临时副本保存源码清单、SHA-256及应用补丁后的哈希，源版本漂移或无效人口直接停止并记录错误。

50/100/200只分别在移动、桥口、步枪场景预热120步并采样300步。300只在移动、桥口、步枪和自动霰弹枪场景，每场墙钟预热10秒、采样60秒、5轮；方案和场景顺序交替反转，不通过短筛选淘汰任何一种本轮优化。全部版本还进行混合、舞王和死亡生成的60秒动态测试；旧版及四项组合分别进行600秒资源周转。固定人口每600步恢复起点，较快版本推进更多模拟时间的局限仍在报告中注明。

日志为cli.log（实时输出）、audit.jsonl（每步命令/时间/退出码/结果）、step-*.log（完整单步输出）、implementation.patch（实施改动）、source-manifest.json和逐帧results.json。summary.json、report.md为最终统计。报告包含平均/P50/P95/P99/最大值、超过16.67ms比例、五轮配对改善方向、节点和敌人峰值、路径预算与排队计数。失败写入progress.json并保留已有数据，不宣称完成。原生GPU、渲染画面、实际音频及真人体验未测，CPU分段不是游戏FPS。

Windows过夜启动可使用 tools/start-cpu-improvements.ps1。启动器为自身生命周期申请临时防自动睡眠，允许显示器关闭，结束时解除；不会改变永久电源设置。手动睡眠、合盖、关机仍会中断测试。启动记录保存在launcher.json，输出保存在console.log及console-error.log。
