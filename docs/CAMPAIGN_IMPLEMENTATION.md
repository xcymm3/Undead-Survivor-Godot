# 灰松渡口：实现与验收边界

版本：1.8.1。设计来源为 `CAMPAIGN_01_GRAYPINE_FERRY.md`。

## 进入与操作

首页选择“灰松渡口”，再选择单人模式；合作房主在房间中选择同名地图后开始合作。战役模式由地图决定，所有队员使用同一房主权威模拟。

- WASD 移动，鼠标瞄准，左键攻击，右键举枪，空格跳跃，Ctrl 蹲下。
- 出发前用数字键选择主武器；出发后保留所选主武器与 7 键消防斧。
- R 换弹，弹药从储备扣除。院落、桥头、工具棚的弹药箱每人每处可领取一次。
- 按住 E 开起点门、启动卷扬机、领取物资或救起队友；目标与读条在 HUD 显示。
- 按住 H 三秒治疗，医疗包最多携带一个；受伤中断，成功后才消耗。
- 合作倒地三十秒后死亡，有效救援暂停倒计时，四秒完成；每关最多被救起两次。死亡后观战，本关不复活。
- 桥头设备启动后九十秒打开北岸闸门；未清完的敌人继续追击。所有未死亡队员进入泵站且屋内无敌人后，按住 E 关门获胜。

## 已接入的系统

独立原生地图包含两间安全屋、废车街道、双出口维修院落、排水巷、控制台、桥梁、浅水河床、北岸闸门、工具棚、泵站服务路及水塔地标。建筑、车辆和路灯使用原生网格；河床渲染、实体碰撞和敌人高度采样使用同一剖面。

战役控制器管理阶段、区域敌人预算、桥头三段尸潮、压力缓解、按人数缩放、补给领取及结算。怪物仍使用共享移动和命中逻辑；服务器检查出生距离、视线、路径、安全屋与活动数量上限。没有可用入口时不积累突发补刷。

合作快照包含战役进度、闸门、补给、储备弹药、医疗包、倒地和完成状态，并经过实际传输层的字段校验。客户端只提交输入，不提交血量、位置、开门或奖励结果。可靠发送最终结果。

第一章结束后显示独立结算；当前没有第二章、途中加入、断线重连、主机迁移或中途存档。这与第一关的实现范围一致。

## 验收方法

`tools/validate-campaign.gd` 通过 `Simulation.submit` 提交移动、瞄准、射击、换弹和交互输入，再推进真实共享模拟和角色胶囊碰撞。单人、双人、四人分别从安全屋出发，通过街道、桥头尸潮、过河和终点关门；单人与四人探索院落，双人走主线。完整路线不传送、不清怪、不添加无敌或额外物资。

同一文件中的独立边界场景会明确设置实体状态，测试部分换弹、受伤打断、并发领取、救援取消、死亡队友、屋内敌人、恶意快照字段和失败重开。这些场景不冒充自然发生的整局试玩。

ENet 验收在真实的 2/4 个进程中检查地图准备、输入、移动、跳跃、蹲伏、射击及快照。战役额外验证客户端开门输入与房主设置的闸门/拾取快照场景。`validate-campaign-network.mjs` 另启真实 ENet 双人/四人进程，每个客户端独立通过正常输入协议走完整关，期间不直接改写权威状态；结果保存为 `artifacts/campaign-enet-*-*.log`。这仍不等于 Steam 双账号跨网络验收。

浏览器验收包含真实按键选择战役并开门，以及显式软件 Web 场景取图。`qa_campaign_gallery.gd` 只在自动化 Web 参数启用时加载，固定视点截图不冒充输入遍历或原生 GPU 画面。提交前必须运行完整验证和源码摘要门禁。

## 节奏与视觉状态

北岸休整最多持续 25 秒；任一站立玩家越过工具棚出口（Z < -82）即结束休整，触发最后路线的区域遭遇。返回工具棚不恢复休整，也不重置区域预算。低血量/倒地触发的独立 8 秒压力缓解仍有效。内部整关验收要求单人、双人和四人在进入终点安全屋前发生最终路段交战，并单独验证工具棚内休整、提前离开和折返行为。

内部测试角色熟悉路线、按真实敌人头部姿态瞄准，并持续移动防守。初步完整路线约 173～191 秒，不能据此声称首次人类通关已经达到设计中的 8～12 分钟。该时间目标仍需在获授权环境中收集人类单人、双人和四人试玩样本校准。

第一轮实际打开软件 Web 截图后发现控制台标牌过大、起点提示遮挡、天空背景下 HUD 对比不足、建筑辨识细节不足，已修改标牌尺寸与位置、HUD 底色，并增加窗门、车轮、路灯、设备及水塔细节。最终截图复查记录写入 `artifacts/visual-review.md`。

遵循 `AGENTS.md`，本机仅运行真正 headless Godot 和独立 headless Chromium，不调用隐藏图形窗口工具。原生 GPU 视觉、连续运动手感、8～12 分钟真人节奏与 Steam 双账号跨网络完整合作均待验收；功能全绿不替代这些结论。

## 单文件 Windows 分发

下载 `Undead-Survivor-Godot.exe` 即可启动，无需另行下载 DLL 或 appid。启动器把游戏、Steam 依赖、许可文件与版本一并嵌入，运行时解压到本次实例的临时目录，退出后清理；存档继续使用 Godot 用户数据目录。

启动器使用 Windows .NET Framework 4.x；Steam 合作需要安装并登录 Steam。成品检查只使用规定的 headless 参数，在只有 EXE 的隔离目录中测试中文/空格路径、并发运行、输出转发和退出清理。正式分发必须使用 GitHub Actions 全绿后产出的文件。
