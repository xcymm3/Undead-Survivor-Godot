# 房主存档合作

## 使用

首页选择“多人合作”进入独立房间浏览页。首次进入会弹出联机须知，必须滚至最底才可确认；取消返回主菜单，右上角按钮可重新打开。顶部可搜索名称或地址，并切换Steam/局域网模式；中间展示房间及人数，点击“加入”进入。底部固定创建房间、直接连接、刷新、退出四项操作；直接连接弹窗输入昵称和房间号或IP端口。已进入房间时，同一页面显示四个队员位置及开始、邀请/复制地址、离开操作。局域网刷新通过UDP27778发现同一网络内可加入的房间，ENet游戏端口默认27777；也可以直接输入房主IP与端口加入。Steam版支持建房、搜索、房间号加入和好友邀请；需要GodotSteam及登录的Steam客户端，当前使用测试App ID 480。普通Godot没有Steam模块时仍可使用局域网。

最多4人，房主点击“开始合作”后加载战场，房主在水晶处长按E修复并开战。战前可以加入，包括房主已经进入整备场景时；第一波开始后成员名单封存，仅原成员可重连，不接受新成员。房主退出关闭房间，不进行房主迁移。

## 成长与收益

- 房主进入房间时当前选择的存档决定全队武器、弹匣、终极技能、手雷上限、天赋与建筑。房主在战前购买后全队立即同步。只有房主能购买、制造和修复水晶开战。
- 所有有效击杀（含客机、炮塔、地雷）金币和清波钻石均归房主，金币动画飞向房主。召唤单位仍不产金币，贪婪按房主等级计算。
- 客机钱包为0金币、0钻石；其临时Store没有文件路径，不替换或写入Progress管理的个人槽位。离房后单人仍使用原存档。胜负后不显示结算弹窗，个人收益仍不会写入客机存档。
- 每人的弹匣、备弹、手雷库存与补充计时、终极技能持续时间和冷却独立。共享升级只改变属性与容量，不能让一人的消耗同步扣除他人的资源。
- 房主收益沿用定时保存，正常退出、结算时保存；异常崩溃不承诺保存最后一次落盘之后的收益。

## 死亡、重连与难度

客机死亡后观战存活且在线的队友，左键切换；实际清完本轮防守后在出生点复活。提前出下一波、退出重进和重连均不能绕过等待。房主死亡或水晶被毁立即结束本次防守，即使其他人仍存活。

通关或失败保留房间，所有玩家依次播放倒下/水晶摧毁或舞王倒下、黑幕与对应文字。全员黑幕文字播放完毕后，由房主自动发起加载握手，一起回到第一波出生点并淡出黑幕，重新初始化生命、弹药、手雷、大招冷却与建筑，沿用房主永久成长。已断线的成员不阻塞新对局加载。房主主动离房仍关闭房间。

战前移动使用独立于战斗计时的同步时钟进行显示插值，破损水晶未修复时也持续同步。队友第3槽显示消防斧或大招长刀，第4槽显示手雷；大招结束恢复对应装备。网络协议为 `undead-survivor-godot-27`，联机双方须使用相同版本。

断线客机的权威玩家记录保留，断线期间冻结状态、不接受输入、不成为敌人目标。重连使用原记录，不重新分配血量、弹药、手雷、补充计时和大招冷却。LAN重连使用房主签发的随机凭据，新ENet连接映射到旧身份；凭据单独保存在`user://coop-reconnect-v1.json`，不属于成长存档。Steam通过传输层提供的账号身份匹配原名单。房间结束或房主程序退出后无法恢复旧对局。

合作出怪预算与单人相同，不按人数放大。普通玩家索敌型僵尸在20米范围内选择比建筑更近且可达的最近存活在线玩家，并保留栅栏拦截。小鬼、巨人、舞王继续只攻击建筑和水晶。

## 验证

`npm run verify`：日常基础检查，包含下述双进程联机回归。

`node tools/validate-coop.mjs`：两个真正headless Godot进程通过ENet进行UDP房间发现与去重、独立页面及搜索/输入检查、建房、握手、共享升级、收益、独立资源、客机存档字节一致性、新身份拒绝、存活及死亡重连、观战和房主死亡结算检查；使用随机本机测试端口与隔离进度，不读写玩家存档。Steam分支使用模拟传输检查成员准入、重连握手、会话校验和邀请API路由，不实际连接Steam。

新增回归覆盖修复水晶前房主移动进入客机显示缓冲、双方队友大招模型与持握节点、斧头/手雷切换、自动接波保留房间，以及房主阵亡和通关后在同一房间连续重开。模型检查仅验证节点和显示状态，不代替GPU画面审查。

ENet本机验证不等于局域网异机、防火墙、延迟丢包、Steam双账号跨网络、好友邀请实机或原生GPU验收。当前任务未运行全量或发布验收，也没有重新导出EXE。
