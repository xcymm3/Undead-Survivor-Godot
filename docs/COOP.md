# 房主存档合作

## 使用

首页选择“多人合作”。局域网房主创建房间，其他人输入房主IP与端口（默认27777）加入。Steam版支持建房、搜索、房间号加入和好友邀请；需要GodotSteam及登录的Steam客户端，当前使用测试App ID 480。普通Godot没有Steam模块时仍可使用局域网。

最多4人，房主点击“开始合作”后加载战场，房主在水晶处长按E修复并开战。战前可以加入，包括房主已经进入整备场景时；第一波开始后成员名单封存，仅原成员可重连，不接受新成员。房主退出关闭房间，不进行房主迁移。

## 成长与收益

- 房主进入房间时当前选择的存档决定全队武器、弹匣、终极技能、手雷上限、天赋与建筑。房主在战前购买后全队立即同步。只有房主能购买、制造和修复水晶开战。
- 所有有效击杀（含客机、炮塔、地雷）金币和清波钻石均归房主，金币动画飞向房主。召唤单位仍不产金币，贪婪按房主等级计算。
- 客机钱包为0金币、0钻石；其临时Store没有文件路径，不替换或写入Progress管理的个人槽位。离房后单人仍使用原存档。客机结算显示个人收益0，并说明收益保存至房主。
- 每人的弹匣、备弹、手雷库存与补充计时、终极技能持续时间和冷却独立。共享升级只改变属性与容量，不能让一人的消耗同步扣除他人的资源。
- 房主收益沿用定时保存，正常退出、结算时保存；异常崩溃不承诺保存最后一次落盘之后的收益。

## 死亡、重连与难度

客机死亡后只能观战存活且在线的队友，左键切换；跨波、退出重进和重连均不复活。房主死亡或水晶被毁立即失败，即使其他人仍存活。重新建立新对局才重新初始化生命和装备。

断线客机的权威玩家记录保留，断线期间冻结状态、不接受输入、不成为敌人目标。重连使用原记录，不重新分配血量、弹药、手雷、补充计时和大招冷却。LAN重连使用房主签发的随机凭据，新ENet连接映射到旧身份；凭据单独保存在`user://coop-reconnect-v1.json`，不属于成长存档。Steam通过传输层提供的账号身份匹配原名单。房间结束或房主程序退出后无法恢复旧对局。

合作出怪预算与单人相同，不按人数放大。普通玩家索敌型僵尸在20米范围内选择比建筑更近且可达的最近存活在线玩家，并保留栅栏拦截。小鬼、巨人、舞王继续只攻击建筑和水晶。

## 验证

`npm run verify`：日常基础检查。

`node tools/validate-coop.mjs`：两个真正headless Godot进程通过ENet进行建房、握手、共享升级、收益、独立资源、客机存档字节一致性、新身份拒绝、存活及死亡重连、观战和房主死亡结算检查；使用随机本机测试端口与隔离进度，不读写玩家存档。Steam分支使用模拟传输检查成员准入、重连握手、会话校验和邀请API路由，不实际连接Steam。

ENet本机验证不等于局域网异机、防火墙、延迟丢包、Steam双账号跨网络、好友邀请实机或原生GPU验收。当前任务未运行全量或发布验收，也没有重新导出EXE。
