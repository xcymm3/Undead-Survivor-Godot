# 灰松渡口：主动推进与节奏校准

本文件记录开发分支的扩展，已发布的 v1.8.1 EXE 不包含这些改动。

## 目标与路线

首次成功真人通关目标仍为8～12分钟，不增加固定等待来凑时长。

值班室 → 废车街道 → 西侧商铺取检修钥匙 → 东侧岗亭解锁通道 → 可选维修院落 → 排水巷 → 90秒河桥事件 → 工具棚 → 西侧泵房复位断路器 → 东侧阀站恢复供电 → 返回安全屋关门。

商铺和岗亭拆成两个接触点，街道隔离栏有实体碰撞与导航阻挡，必须携带本队共享钥匙到岗亭交互解锁。支线院落仍可跳过，补给不参与主线解锁。北岸泵房为可进入的原生房间，供电操作要求先修泵房再到阀站，最后的安全屋门在供电前保持关闭。所有交互都由房主检查位置、视线、前置条件与读条；客户端只发送输入。

交互时间：取钥匙1秒、岗亭开锁2秒、泵房复位3秒、阀站供电3秒。操作期间可以被伤害打断。桥头仍为90秒，区域遭遇仍有40秒尝试生成窗口，区域预算耗尽或窗口到期就停止；不靠无限尸潮延长路线。工具棚休整最多25秒，队伍离开后结束，最终遭遇启动后不因折返恢复。

## 遭遇与资源

沿用六种僵尸。新增商铺14、岗亭14、泵房18、阀站16的单人上限，分别在进入对应区域时激活；原有区域预算不变。新增区域与原有区域共享活动上限、生成速率、视线/距离/可达性保护和低血量缓解。新增商铺、泵房和阀站的每人一次弹药，泵房增加一份共享医疗；不会因回头刷新资源。

## 校准方法

功能基线继续使用精准瞄准、既知路线角色，单人、双人、四人走完整关；真实 ENet 2/4人通过相同输入和世界快照协议验证必需目标。

新增 `tools/validate-campaign-calibration.gd`，每档使用相同两个固定种子，不因失败重抽：

| 参数 | 标准受限 | 保守受限 |
|---|---:|---:|
| 最大转向速度 | 120度/秒 | 85度/秒 |
| 周期性瞄准误差幅度 | 0.7度 | 1.2度 |
| 对准后反应时间 | 0.25秒 | 0.4秒 |
| 交互点/明显转角观察停顿 | 1.5秒 | 3秒 |

移动速度与游戏一致，敌人接近10米时取消观察停顿，模拟继续运行，敌人不会因测试角色观察而暂停。医疗、弹药、伤害和死亡均走正常规则。逐帧检查转向上限；观察暂停结束后能够继续移动也有回归检查。

报告 `artifacts/campaign-calibration.json` 按街道/商铺、院落/排水巷、桥头、泵房、阀站、撤离记录起止时刻、血量与击杀，保留失败、超时与资源余额。自动流水线中的 calibration 通过仅表示报告生成且输入限制检查通过，不表示所有角色获胜或平衡达标。初始失败版本的报告保存在 artifacts/campaign-calibration-initial.json。

上述角色知道路线并读取敌人遥测，误差和观察时间是明确的合成参数，尚未用真人样本拟合；不能声称是新手模型，不能拿其通关时间替代8～12分钟人类首次试玩。真人校准应分别招募不了解地图的单人/双人/四人样本，记录成功时间、死亡重试、迷路、阶段停留及剩余资源，再调整路线、遭遇和指引，而非直接提高血量或等待时间。

## 视觉验收

软件 Web 图集新增商铺、泵房、阀站视点，必须实际打开检查可读性、入口与设备位置。记录见 artifacts/visual-review.md。本机仅真正 headless Godot 和独立 headless Chromium；原生GPU、连续操作手感和Steam跨账号验证待验收。


## 待试玩改造：死亡诊断、泵房推进与守路者

本轮按用户要求不运行试玩，不沿用上轮验收结论。仅进行源码检查与 headless 导入解析；没有新的通关、平衡或视觉通过结论，不提交、不发布 EXE。

- 泵房：入口左侧隔离阀按 E 2 秒，再沿黄色检修线从设备右侧绕行至后方断路器按 E 3 秒；未关阀不能复位。设备共享原生碰撞和导航障碍。随后仍前往东侧供电台，恢复终点门供电。新增里程碑 `leak`。
- 守路者：开局固定布置 10 只，街道 2、商铺 1、泵房 3、终点路 2、东侧供电台 2，普通/路障类型。14 米内看到玩家或自身受伤后进入常规追击，不重生、不补位、不强制清光才能推进。对应区域随机刷新预算扣除固定数量，不增加总预算。未唤醒守路者不占动态刷新活跃上限；唤醒可能短时超出活跃上限，但动态刷新会等待回落。
- 指引：新增入口、路口、设备标识和泵房黄色检修线；HUD 每半秒按导航下一节点更新相对方向，同时标明到目标的直线距离，交互提示优先。桥头事件期间提示防守。
- 诊断：权威端保留最近 256 次有效伤害及各敌人原始类型的累计有效伤害，倒地、死亡、流血耗尽、团灭记录模拟时间、阶段、坐标、最后一击、弹药、医疗包和 10 米内敌人数。倒地/死亡/团灭/通关时写入 `user://campaign-diagnostics-*.json`；每局独立文件。校准报告直接嵌入同一诊断数据，成功失败均保留。`team_wipe` 表示全队失去行动能力，不把仍倒地的角色误记为流血死亡。
- 后续验收：先检查隔离阀前置条件、设备绕行导航、守路者激活与预算、诊断文件；再按固定种子跑完整样本。需复查 960/1440/1920 下入口、隔离阀、设备两侧、断路器、返程路口和 HUD 的文字遮挡、路径可读性及敌人可见性。当前没有生成或审查本轮截图；软件 Web 与原生 GPU 视觉均待验收。遵守 AGENTS.md，禁止使用 VISUAL_QA.md 中已被覆盖的隐藏图形窗口方案。
