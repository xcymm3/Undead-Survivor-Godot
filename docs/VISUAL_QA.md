# 视觉质量验收计划

视觉质量是独立的必检项。`npm run verify` 的真实键鼠流程验证操作与状态，非空白检测只验证基础渲染；两者不能代替逐图审查。

## 执行顺序

1. 本机只允许真正 headless Godot 与独立 headless Chromium。原生 GPU 截图必须另获隔离环境授权，未获得时明确记为待验收。
2. 禁止运行 `capture-hidden.ps1`、隐藏父窗口、离屏 SubViewport 或先启动再隐藏的本机图形进程。软件 Web 图库由 headless Chromium / SwiftShader 生成，设置场景与姿态用于画面检查，不冒充键鼠试玩或原生 GPU 验收。
3. 实际打开原尺寸截图；缩略联系表只用于定位，文字、瞄具、接缝和疑点必须打开单图。检查以下矩阵，并记录通过、缺陷或未覆盖。
4. 缺陷修复后重拍受影响画面；影响公共材质、布局或渲染逻辑的修改应重拍全部矩阵。禁止用修图替代游戏内修复。
5. 运行 `npm run verify`，实际打开其中的浏览器流程截图，检查交互后状态。报告分别记录原生 GPU 与软件 Web 的观察，不混称同一渲染验收。
6. 在 `artifacts/visual-review.md` 记录源码、GPU、分辨率、截图、问题及复查结论。代码或美术改变后旧结论失效。提交前执行源码摘要门禁。

## 检查矩阵

| 范围 | 必查画面 | 判定重点 |
| --- | --- | --- |
| 首页 | 夜路唯一入口，960×540、1440×900、1920×1080 | 按钮与标题无重叠、裁切，选中态与背景对应 |
| 菜单 | 设置、说明、多人入口、暂停、结算 | 字体可读、行列对齐、文本完整、遮罩层次 |
| 战斗 | 十种武器腰射与瞄准、全部敌人、单人/双人 HUD | 模型缺失、瞄具遮挡、准星、文字溢出、角色遮挡 |
| 灰松夜路 | 街口、店铺、林缘、暖灯安全屋，960 / 1440 / 1920 宽度 | 黑暗中主路可辨、敌人受遮挡、待机手臂下垂、光照接缝与双人血卡；比较不同时间的待机姿态 |
| 实际操作 | 夜路浏览器开始、换弹、开镜、推击、暂停和重开截图 | 操作后的 UI/画面状态正确、无残留遮罩或空白 |
| 左轮样板 | 无手臂持枪、行走左右、开镜、射击、逐阶段换弹、收拔枪、中断与死亡，连续播放录像 | 全阶段无第一人称手掌/手臂，装填器与弹巢对齐、准星可见、无遗留零件，其他武器无新增手臂 |
| 贴墙光照 | 夜路安全屋与商铺距墙约 0.32 米，左右转向连续取样，开关手电筒投影与全部阴影对照 | 光斑不偏离视线、不突发遮黑或过曝；阴影设置覆盖手电筒、太阳和所有路灯 |
| 门前坚守 | 未启动、倒计时 15 秒、解锁后三张门前画面，双人 HUD | 门的关闭/打开状态一致，倒计时与指引可读，无重叠标牌 |
| 本次试玩反馈 | 三处照明挂墙武器架、单/双人拾取后空位、后方受击方向弧及中文提示 | 枪身不埋墙、站立视角可见，提示不遮准星；脚步/推击音效路由自动检查，真人听感待验 |
| 近身战斗 | 奔跑左右步、攻击前摇/挥击/收势、推击动作、准星上方冷却环与恢复后 | CPU/GPU 姿态一致、四肢动作可辨、无第一人称手臂残留、冷却环不遮挡准星；音效事件及资源校验，真人听感另验 |

报告需明确尚未覆盖的连续运动、不同 GPU、超宽屏或 Steam 实际多人场景。单帧矩阵不能证明所有角度、动画瞬间、主观手感。
